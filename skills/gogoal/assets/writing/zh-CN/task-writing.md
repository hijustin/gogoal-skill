# AI 任务文档写作要求

任务文档应紧凑、可执行、可验证，不复制 JSON 状态、时间或管理日志。简单任务使用短段落或小表格，复杂任务可以增加必要内部小节。

```md
# A-<任务编号> <任务标题>

> 关联目标：[G-<目标编号>](../targets/<目标编号>.md)

## 1. 任务定义

说明预期结果、范围、非目标和依赖。

## 2. 实施计划

说明步骤、对规范/文档/功能/配置/测试的影响检查、风险与恢复方式、完成条件和验证计划。

## 3. 实施记录

说明实际改动和与计划的重要偏差，不把计划事后改写成结果。

## 4. 验证结果

区分实际检查或命令、客观结果、AI 结论和未执行验证及原因，不粘贴完整终端日志。

## 5. 交付结果

说明最终产物、使用或合入方式、已知限制以及分支或工作树清理结果。

## 6. 阻塞、恢复与取消记录

只记录异常的原因、已尝试措施、解除条件和已有改动处置；没有异常时写“无”。
```

各章各司其职，避免重复。大量同构信息优先使用表格，复杂关系可以使用 Mermaid。
